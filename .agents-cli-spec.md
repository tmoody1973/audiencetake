# Agent Spec: Project-Native Pathway Hypotheses

## Overview

Audience Take's existing six-stage Scout workflow must generate exactly three evidence-linked
development, distribution, or audience-growth pathways that fit the submitted project's actual
medium, form, and lifecycle. The current Junichiro-only animation blueprints will be removed from
the reusable pathway boundary. Cross-format adaptation may appear only when qualified cited evidence
explicitly supports it; otherwise every pathway remains native to the researched project.

This remains the existing single ADK workflow on private Cloud Run. It does not add a sub-agent,
provider, search call, authentication method, or model change.

## Approaches Considered

1. **Project-native pathways (selected):** Classify the evidenced project profile, let the bounded
   pathway stage author three distinct strategies within that profile, and enforce compatibility in
   deterministic code. This preserves relevance and blocks the documentary/animation contradiction.
2. **Fixed templates per genre:** Maintain separate hard-coded triplets for documentary, animation,
   and live action. This is simpler initially but recreates the same rigidity as the Junichiro-only
   implementation and will fail on hybrid or unfamiliar projects.
3. **Unrestricted model-authored pathways:** Let Gemini choose any labels and formats. This is
   flexible but cannot guarantee that a pathway fits the evidenced project or that cross-format
   adaptation is properly supported.

The selected approach combines bounded model authorship with deterministic compatibility checks.

## Example Use Cases

- A completed documentary receives three native pathways such as theatrical/festival expansion,
  broadcast or streaming distribution, and educational/community licensing.
- An animated proof of concept may receive serialized animation, independent animated feature, and
  creator-direct animation pathways when its evidence supports those directions.
- A live-action short receives pathways appropriate to live-action development and distribution;
  it cannot silently become an animated series.
- A project with insufficient medium evidence receives medium-neutral validation, packaging, and
  discovery pathways rather than a guessed format.
- A cross-format adaptation is allowed only when at least one exact qualified claim and its cited
  source explicitly support that adaptation.

## Architecture & Data Flow

1. The existing source analysis and bounded Parallel research remain unchanged.
2. Stage 4 persists a strict `projectProfile` alongside the evidence ledger:
   - `medium`: `documentary`, `live_action`, `animation`, `hybrid`, or `unknown`
   - `form`: `feature`, `short`, `series`, `proof_of_concept`, `campaign`, or `unknown`
   - `lifecycle`: `development`, `production`, `released`, `campaigning`, or `unknown`
   - exact supporting source IDs and a bounded qualification
3. Stage 5 returns exactly three typed pathway drafts. The model authors bounded labels, formats,
   strategy content, and evidence references; the application injects fixed IDs, order, project ID,
   and run ID.
4. Deterministic validation compares each proposed medium with `projectProfile.medium`. A different
   medium requires explicit cross-format status plus at least one qualified evidence claim whose
   exact source references are present in the ledger. Inference-only or unsupported claims cannot
   authorize a cross-format pathway.
5. Stage 6 publishes only pathways that pass the compatibility guard. The Scout Card and Industry
   Lens continue rendering the same canonical pathway records, so both views remain consistent.
6. Existing immutable cards are never overwritten. The American Pachuco card receives a new public
   correction version derived from its already-persisted evidence and sources; the original remains
   in its audit history.

## Constraints & Safety Rules

- Never inject Junichiro-specific labels or animation formats into a reusable project run.
- Never infer a project medium solely from a nominator assertion when cited public evidence conflicts.
- Never treat `inference` or `unsupported` evidence as sufficient authorization for a cross-format
  adaptation.
- Never publish three pathways with duplicate labels, formats, or strategy purposes.
- Never publish a pathway whose medium contradicts the evidenced project profile.
- When medium is `unknown`, use medium-neutral pathways and disclose the classification limitation.
- Preserve exactly three bounded pathways and the existing evidence/citation requirements.
- Preserve model pin, provider count, authentication, privacy boundaries, rate limits, runtime
  identity, secret binding, and task retry suppression.
- Keep the research queue paused until the corrected revision and regression suite are approved.
- Do not prepare attempt 4 or another provider-bearing run for the American Pachuco correction.
- Correct the published card through an immutable correction version, never an in-place rewrite.

## Edge Cases to Handle

- Hybrid animation/live-action work.
- A campaign page for a documentary whose trailer is hosted separately.
- A proof of concept whose intended final medium is explicitly evidenced.
- Conflicting sources about medium or lifecycle.
- Unknown or weakly evidenced project type.
- Credibly evidenced cross-format adaptation.
- A model returning an animation label while declaring a documentary medium.

## Success Criteria

- Four evaluation fixtures—documentary, animation, live action, and unknown—each produce exactly
  three schema-valid, evidence-linked pathways.
- All incompatible native-medium fixtures are rejected deterministically before publication.
- All cross-format fixtures lacking a qualified exact claim are rejected deterministically.
- The Junichiro animation fixture retains animation-appropriate pathways.
- The corrected American Pachuco pathway labels and formats contain no animation direction unless a
  qualified cited claim explicitly supports it; its selected correction uses none.
- The Pathway Hypotheses section and expanded Industry Lens show the same three corrected pathways.
- Existing contract fixtures, complete Python suite, Ruff, strict mypy, web suite, lint, typecheck,
  and production build pass.
- The corrected production card route returns `200`, its immutable correction history is public,
  the Cloud Run revision has no run-specific errors, and the queue is resumed only after verification.

## Future Phase: Gemini Trailer Critic

After the project-native pathway correction is deployed and verified, add a dedicated reusable
Trailer Critic stage for public YouTube trailers and proof-of-concept videos. This phase is
intentionally sequenced after the pathway repair and is not part of the correction deployment.

- Use the intended Gemini 3.7 Flash video-understanding model only after confirming current Vertex
  availability in the deployed region; preserve the existing research model pin otherwise.
- Analyze the submitted YouTube video together with the card's already-researched public sources.
- Return bounded sections for structural/narrative analysis, technical craft, marketing/persuasion,
  emotional/rhetorical analysis, and a compact critic matrix.
- Ground visual and audio observations with timestamps; keep public-source factual claims cited by
  exact source IDs.
- Disclose sampling limitations for rapid edits and do not claim frame-perfect inspection, rights,
  creator identity, audience response, or private analytics.
- Persist the result as an independently reusable, immutable video-analysis artifact so a reviewed
  YouTube video added later can receive analysis without rerunning unrelated Parallel research.
- Define and approve a separate behavioral evaluation set before deploying this phase.

## Assumptions

- Project-native pathways are the default approved product behavior.
- Cross-format adaptation is exceptional and requires qualified cited evidence.
- Existing Firebase, Vercel, Cloud Run, Gemini, and Parallel architecture remains unchanged.
- The current American Pachuco correction reuses durable evidence and makes no new provider call.
- The Trailer Critic begins only after this pathway correction passes production verification.
